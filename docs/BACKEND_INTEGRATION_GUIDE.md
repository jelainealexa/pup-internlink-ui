# Replacing demonstration services

Actual backend/server/database integration is outside this delivery. No approved ERD/API/session/rubric was supplied. The proposed REST contract is in API_CONTRACT; the implemented UI boundary is `InternLinkService` in `app/lib/domain.ts`.

1. Agree entity keys/DTOs, term model, account provisioning, role/assignment matrix, approval/eligibility/capacity/hour/completion policies, rubric and certificate authority. Reconcile the PDF's submitted-documents wording with the stricter demo approval policy.
2. Implement an API client class that satisfies InternLinkService. Map approved transport DTOs to the existing front-end records. `read()` returns authorized related data and authoritative availability, never unrelated private records or credential hashes. Pagination/resource caches may be internal to the adapter; presentation need not open IndexedDB or parse transport errors.
3. Replace `UnconnectedApiService` composition in `createService`. API mode must never instantiate IndexedDbStore, read synthetic sessions or use demo data on network/auth errors. No API base URL or credentials are currently configured. Validate/decode unknown responses at runtime.
4. Map each typed Command to an authorized server mutation. Derive actor, timestamps, ownership, related context and IDs on the server. Preserve error codes, request IDs/idempotency and revision/conflict behavior; reread authoritative affected records after mutations. Reject illegal transitions atomically.
5. Replace local session markers with backend-approved secure sessions, expiry/logout and CSRF/CORS handling. Do not send the synthetic verifier or public demo password as production credentials. Client guards remain usability aids; all reads/files/commands need server authorization.
6. Implement private file upload/download: multipart upload or approved signed-upload flow, metadata/content validation, malware scanning, quotas/retention and expiring access URLs. Convert authorized downloads to Attachment Blob objects if retaining the current preview UI. Failed upload must not create a successful submission. Remove orphan files transactionally or via a documented cleanup policy.
7. Replace subscribe with authorized refresh/poll/events as appropriate. Server errors must remain visible and preserve form input; do not silently seed data. Demo reset must be unavailable in API mode. Use isolated environments/origins and separate adapters.
8. Run adapter contract tests and all lifecycle/authorization/capacity/duplicate tests against a dedicated synthetic backend environment, including simultaneous independent clients. Front-end tests passing against IndexedDB do not prove server correctness.

Backend constraints include unique case-insensitive account email/student number/company name/company email/certificate number; valid profile roles/FKs; application uniqueness; placement-per-application uniqueness; appropriate ongoing-placement policy; supervisor company affiliation; accepted application and document eligibility; atomic capacity; one report per placement/date; exactly two assigned evaluator obligations and one submission per obligation; immutable decision/review attribution; completion/certificate validity. Define reassignment/history/retirement rather than deleting referenced records.

Concurrent last-slot creation must serialize or use a transactional conditional allocation; a UI precheck is insufficient. Repeat requests with the same authenticated actor/idempotency key must return the same logical result, with conflict behavior for payload mismatch. Specify idempotency retention longer than the bounded demo receipt cache if required. Separate production data versioning from IndexedDB schema version.

Attachment bytes need not be downloaded with every API read. Presentation components request them exclusively through `service.attachment(id)`; the `files` collection is needed by the demonstration store and may be empty in the API read projection while the adapter fetches authorized bytes on demand. Keep metadata/upload references in the transport adapter and resolve fileId on the server. Never substitute an empty Blob for a successful upload/download.

Receiving-team verification must cover unauthenticated/forbidden detail URLs, list-scope leaks, attachment access, inactive accounts, token/session expiry, duplicate retries, stale revisions, network timeouts, upload failure, rollback and multi-client allocation. No real credentials or student records should be introduced into test fixtures.
