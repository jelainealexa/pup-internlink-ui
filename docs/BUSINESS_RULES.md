## Adopted demonstration policies

These resolve BR-Q01–18 from the historical audit for independent front-end operation; institutional approval is still required before real integration. Decisions D-016–026 contain rationale.

Every production invariant, permission and relationship must be enforced again by the server/database, including idempotent duplicate prevention and transactional capacity. Browser-local data and client guards cannot protect data from their profile owner. No unresolved policy is silently claimed as owner-approved.

Engineering bounds are demonstration choices: capacity and required hours cannot exceed 10,000; daily report hours cannot exceed 12. Date-only comparisons use the UTC ISO calendar day, while audit timestamps display in the browser's locale. The receiving team must agree institutional timezone/calendar and maximum values before real integration.

## Verification clarifications

See D-033–040 for repaired demonstration engineering behavior. Fractional hours use a shared compensated sum with twelve significant digits and consistent forms; rendered hours include attendance once and the latest daily attempt; approved totals come from Approved reports (including migrated Reviewed history). Academic years require a consecutive pair; phone format requires five digits. These are demo guards rather than approved institutional maxima/precision/catalog rules. Reset can sign out before a failed database replacement but never intentionally reseeds during ordinary reads.

## Updated role, account and reporting policies

D-043–052 record these as demonstration assumptions, not approved institutional rules.

- Faculty pre-registration automatically assigns that student to the acting adviser. Only coordinators reassign; one current adviser per student. Reassignment conflicting with an ongoing placement is blocked. Historical closed placement/evaluator relations remain; old advisers cannot review new documents after reassignment.
- Pre-registration creates the existing linked account as Pending Activation, distinct from Deactivated. Invitation lifetime24 hours, reset 15minutes; both account-bound and single-use. Issuing a new request invalidates the earlier request of that purpose. Activation matches invitation, student number and email. Recovery cannot activate pending/deactivated accounts. Password policy8–128 characters, at least one letter and digit. Credentials are hashed using the existing demo verifier; this is not production password security. Credential changes revoke versioned sessions and outstanding requests.
- Legacy operational Company Supervisor accounts become Intern Supervisor without broader privileges. New company administrators are explicitly created by a coordinator; administrators create only own-company Intern accounts. They may edit ordinary company information but cannot approve/change MOAs. Active placement/evaluation history is never deleted by deactivation.
- Intern Supervisors decide only applications to assigned opportunities; relevant Before documents are visible for that review, unrelated student documents remain hidden. The updated PDF describes coordinator monitoring without explicitly revoking original coordinator decisions: the reversible demo retains coordinator oversight decisions through the same single terminal transition. Acceptance creates no placement. Capacity is consumed only by non-terminated placements, including completed ones; accepted applications reserve none.
- Approved posting activation requires both current approvals (or explicit legacy provenance), current company eligibility and an active assigned Intern Supervisor. Deactivation retains all records. Removing assignments preserves placement history. Inactive Interns with ongoing placements must be reassigned first; removing posting assignment does not silently transfer placed interns.
- Weekly reports cover1–7 calendar days within placement and through today. Selected unreported/rejected attendance determines hours. Daily attendance is positive≤12 hours/date; weekly totals can exceed12. A rejected weekly attempt releases entries for a replacement but preserves earlier report/decision history. Pending/approved entries cannot be reused. The latest daily alternative attempt supplies rendered hours; a replacement must reference the rejected report for the same placement/date. Attendance and daily alternatives cannot overlap.
- Faculty monitoring remarks are append-only records independent of supervisor state, remarks and approved hours. Missing-report flags use seven days as a local demonstration reminder, not an official attendance or reporting policy.
- Only Before mandatory definitions gate initial acceptance/placement. Placement creation freezes all currently mandatory phase IDs for completion; During/After obligations are completed later. New mandatory definitions do not retroactively invalidate an existing placement. Rejected reports do not add approved hours; pending reports/unreported attendance block completion.
- Exactly two evaluation obligations remain: one assigned faculty and one assigned Intern Supervisor. Explicit evaluation dates must be from placement start through today. Score0–100/comments remain a demo rubric, without pass threshold/weighted final grade. Pending obligation reassignment changes evaluator in-place and is audited; a submitted company evaluation is retained and blocks ongoing reassignment.

Institutional assignment cardinality/reassignment, coordinator override authority, phase eligibility wording, MOA thresholds, slot consumption, weekly attendance correction/report policy, grade rubric, completion and certificate authority still need owner/backend agreement. No UI policy is represented as an approved ERD rule.

## Final review clarifications

- Administrative activation or email changes revoke that account's existing demonstration session versions and unused activation/reset requests. Ordinary name, program or phone edits do not revoke sessions. This includes student, faculty and supervisor maintenance as well as Settings credential changes; it is not production authentication.
- Active posting state differs from application availability. Existing Active records may outlive MOA expiry; they remain unavailable for applications. Explicit activation requires the documented current approved MOA and active assigned Intern. Coordinator summaries retain both Active and Available counters. Filled derives from non-terminated placement allocation and is used consistently in directory, details, reports and CSV.
- Reports expose both pending approval stages, Approved, Active, Filled, Deactivated and Rejected. The existing Pending Approval filter groups both stages; the legacy programmatic Closed filter aliases Deactivated. This preserves report filtering without reinstating obsolete writable states.
- Ordinary student directories filter the student's recorded academic year. My Interns (`interns=true`) instead selects authorized students with placements in the selected placement year, so registration cohorts are not hidden. Student directory shows rendered and approved totals separately; `sort=hours` follows the original rendered-hours requirement, while `sort=approvedHours` retains approved ordering. Official completion still uses approved hours only.
